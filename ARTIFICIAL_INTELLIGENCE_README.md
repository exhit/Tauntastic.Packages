Package "com.tauntastic.packages" (Editor-only assembly and namespace Tauntastic.Packages.Editor, no dependencies): update notifications for Tauntastic packages installed from a GitHub git URL, which the Package Manager does not provide. It works on its own once imported, so do not write code to start it: on Editor start (at most once per interval, default 2 hours, skipped in batch mode and when offline; opening the Updates window with no results also calls PackageUpdateChecker.ScanIfEmptyAndDue(), which scans only when PackageUpdateSettings.IsAutomaticCheckDue() is true, so it obeys the same Enabled switch and IntervalHours limit) PackageUpdateChecker lists the registered packages whose name starts with "com.tauntastic." and whose source is Git, parses each package id with GitPackageReference.TryParse (GitHub HTTPS only; supports ?path= sub folders; a commit hash or version tag ref means follow the default branch HEAD, any other ref is a branch), downloads raw.githubusercontent.com/<owner>/<repo>/<branch>/package.json with UnityWebRequest, and compares its "version" with the installed one using PackageVersion.IsNewer(candidate, current) (major.minor.patch with optional pre-release tag; a release is newer than its pre-release). The Updates window shows one colored flag per package and per kind of failure (PackageFailureKind: NotFoundOrPrivate red, TokenRejected purple, Network blue, InvalidResponse amber; UpToDate green, UpdateAvailable orange, Checking gray, all from PackageStatusStyle), a strip of counts, and the number of updates in the tab title. When updates exist it logs a warning per package with the changelog URL and opens the PackageUpdateWindow once per distinct set of updates. Menus (kept first in Tools > Tauntastic by negative MenuItem priorities in PackageMenuPriority, and this package is also sorted first in the results list): Tools > Tauntastic > Packages > Updates (window with Check now, Update, Changelog and Repository buttons) and Check For Updates (forced, always reports). Settings are per-user EditorPrefs under Preferences > Tools > Tauntastic > Packages (PackageUpdateSettings: Enabled, IntervalHours, OpenWindowOnUpdate). From code use PackageUpdateChecker.CheckNow(bool userInitiated), the read-only Results (PackageUpdateInfo with Name, DisplayName, InstalledVersion, LatestVersion, Status Checking, UpToDate, UpdateAvailable or Failed, Error, Reference) and the Changed event, and PackageUpdateChecker.Update(info) which calls Client.Add with the branch URL (this unpins commit hashes and tags). For updates to be detected, a package repository must raise "version" in its package.json when releasing, and private GitHub repositories are only checked when the user sets an optional token in the preferences (PackageUpdateSettings.GitHubToken, a fine-grained personal access token with read-only Contents access, stored in plain text in EditorPrefs and sent only as an Authorization Bearer header to api.github.com, which is used instead of the raw URL whenever a token is set so errors include GitHub's own message), otherwise a 404 is reported as "not found or private"; never log, print or commit the token. Packages stored inside Assets or Packages folders, registry packages and non-GitHub hosts are ignored. Discovery of packages that are not installed (PackageUpdateSettings.DiscoverPackages default on, GitHubOwner default exhit, repository name prefix "Tauntastic."): the checker lists the owner's repositories through api.github.com (users/{owner}/repos, or user/repos with a token so private ones appear, paged by 100), reads the root package.json of every matching repository that is not installed with GitHubRepository.ParseList, PackageManifest.TryParse (needs a name and a valid version, which is what defines a Unity package) and a 404 or invalid file means the repository is skipped, and adds the rest to Results with Status Installable, or with Status SourceFolder (flag SOURCE CODE, indigo, SourceFolderPath and SourceFolderVersion set, no Install button, only Open folder, never installed from git) when the project already has a folder with that package under Assets or Packages (found by scanning package.json files and matching ProjectPackageFolder.Matches on package name, repository url or folder name) (flag INSTALLABLE, teal) and IsInstalled false; install them with PackageUpdateChecker.Install(info) (Client.Add of the branch URL, Unity also installs git-URL dependencies) and read PackageUpdateChecker.DiscoveryError when listing failed. The toolbar buttons Update all (packages with Status UpdateAvailable) and Install all (Status Installable), each shown only when it has something to do, call PackageUpdateChecker.UpdateAll(includeUpdates, includeInstalls) after a confirmation list, in one Client.AddAndRemove call, ordered by PackageDependencyGraph.GetInstallOrder from the top of the dependency tree (grandparents, packages that nothing else in the list needs) down to the deepest dependencies (grandchildren), alphabetical within a level, and PackageUpdateChecker.GetPendingInTreeOrder() returns that list without running it; SourceFolder, Failed and UpToDate packages are never included. Each row also gets a PRIVATE (dark gray) or PUBLIC (green) flag from PackageUpdateInfo.IsPrivateRepository when IsVisibilityKnown is true, which is set from the owner's repository list for installable, source code and installed packages alike. Source code packages (Status SourceFolder) whose package.json version is higher than the repository version have SourceAhead true (flag SOURCE AHEAD: UPDATE, counted as an update); their git state is read in the background with GitRepository.Inspect (GitState: ChangedFiles, AheadCount, HasUpstream, CanCommit, CanPush) and stored in PackageUpdateInfo.Git, and PackageUpdateChecker.RunGit(GitAction.Commit, Push or CommitAndPush, packages) commits with the package.json version as the message and/or pushes each package only when it is eligible, with GetEligibleSourcePackages(action) listing them in dependency tree order; the window offers this as a Git dropdown on each source row and a Source code dropdown in the toolbar (Commit all, Push all, Commit & Push all if eligible). Each row of the window is itself a foldout (PackageUpdateWindow keeps the collapsed package names in a serialized list; collapsed rows show only the header line with name, versions and flags) with Expand all and Collapse all buttons in the toolbar, and has a Dependencies foldout fed by PackageDependencyGraph built from the dependencies of all known package.json files: PackageUpdateChecker.GetDependencies(info) returns the child dependencies (what it needs, direct and indirect, DependencyEntry with Name and Depth) and GetDependents(info) the parent dependencies (known packages that need it), and DescribeDependency(name) says installed, installable or not installed. JSON is read with the SimpleJson helper because JsonUtility cannot read dictionaries. GitHubTokenTester.Test() asks api.github.com/rate_limit whether the saved token is accepted and reports status, rate limit and expiry, and GitHubTokenTester.TestClipboard() tests the clipboard text without saving it and reports whether it is identical to the saved token, and GitHubTokenTester.Describe(token) describes a token without revealing it (length, github_pat_ or ghp_ kind, last four characters, stray characters), which is also appended to TOKEN REJECTED errors. Never reference these Editor types from runtime code, and do not poll faster than the interval to avoid hitting GitHub rate limits.
